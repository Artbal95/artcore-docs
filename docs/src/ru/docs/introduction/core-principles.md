# Основные принципы ArtCore

ArtCore строится не вокруг папок или технологий.

Он строится вокруг набора правил, которые определяют поведение всей системы.

Эти правила важнее структуры.

## 1. Изоляция важнее переиспользования

В традиционных подходах часто стремятся к максимальному reuse кода.

В ArtCore приоритет другой:

> сначала изоляция, потом переиспользование

Если что-то можно переиспользовать, но это ломает границы — это ошибка архитектуры.

## 2. Каждая сущность должна иметь чёткий контекст

Любой модуль, фича или сущность должна отвечать только за свою область ответственности.

Никакой “размазанной логики”.

Если нельзя объяснить, где живёт ответственность — значит архитектура нарушена.

## 3. Shared — это исключение, а не база

shared не является основным местом для логики.

Он используется только для:

- действительно универсальных утилит
- нейтральных UI компонентов
- инфраструктурных вещей

Всё остальное должно жить внутри своего контекста.

## 4. Зависимости направлены вниз

Система строится как слои.

Высокие уровни могут использовать низкие.

Но не наоборот.

Это создаёт предсказуемый поток зависимостей.

## 5. Бизнес-логика ближе к домену

Логика должна находиться максимально близко к своей предметной области.

Не в shared.
Не в utils.
Не в глобальных сервисах.

А внутри своего модуля или сущности.

## 6. Минимум глобального состояния

Глобальное состояние — источник скрытых зависимостей.

В ArtCore:

- глобальное состояние ограничено
- предпочтение локальному состоянию
- связь через явные интерфейсы

## 7. Явность важнее магии

Архитектура должна быть читаемой без “догадок”.

Если нужно долго разбираться, где что находится — это проблема дизайна.

## 8. Каждый модуль — это мини-система

Модуль в ArtCore — это не просто папка.

Это автономная единица, внутри которой есть:

- UI
- логика
- состояние
- типы
- бизнес-правила

## Итог

ArtCore не диктует “как писать код”.

Он задаёт правила, которые делают рост системы предсказуемым.

> Чем больше проект — тем важнее ограничения.
